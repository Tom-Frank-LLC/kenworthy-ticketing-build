# RUNBOOK: build, sign and distribute the Android app

The Kenworthy Android app is the website's production build, bundled into the
same Capacitor shell as the iOS app (`android/`, `capacitor.config.ts`). What
was measured in the Android WebView: `docs/FINDINGS-android-webview.md`. Why
the shell is built this way at all: `docs/briefs/BRIEF-capacitor-ios-app.md`
and `docs/briefs/BRIEF-capacitor-android-app.md`.

| | |
|---|---|
| Application id | `org.kenworthy.tickets` (same as iOS; permanent once on Play) |
| Display name | Kenworthy |
| Capacitor | 8.5.x; plugins `@capacitor/app`, `@capacitor/status-bar` |
| Min / target SDK | 24 (Android 7) / 36 (Android 16) |
| Permissions | `INTERNET`, `CAMERA` (door scanner). Nothing else. |

## The app does not update itself

Same as iOS: the web code is inside the binary. **A website deploy does not
change the app.** Cut a new build after any production deploy that touches
`src/`, `public/` or `index.html` and matters on a phone.

## What you need

Any Mac, Linux or Windows machine with Android Studio (it brings the SDK) and
JDK 21. No Mac requirement, unlike iOS. On Tom's Mac: SDK at
`~/Library/Android/sdk`, JDK `$(/usr/libexec/java_home -v 21)`, emulator AVD
`Medium_Phone_API_37.0`.

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 21) ANDROID_HOME=~/Library/Android/sdk
```

`android/local.properties` (gitignored) is written by `cap add`/Android Studio
and points Gradle at the SDK; `ANDROID_HOME` does the same.

## Build

From a clean worktree (CLAUDE.md, "Working in this repo"):

```sh
npm ci
npm run android:prep
cd android && ./gradlew bundleRelease     # → app/build/outputs/bundle/release/app-release.aab
                                          # or assembleRelease → apk/release/app-release.apk
```

`android:prep` runs, in order, and stops at the first failure:

1. `build:native`: the production build with no service worker, into
   `dist-native/` (shared with iOS).
2. `cap sync android`: copies it into `android/app/src/main/assets/public`,
   behind the same `scripts/verify-native-bundle.mjs` guard as iOS.
3. `scripts/stamp-android-build.mjs`: writes `android/app/version.properties`
   with the versionCode (minutes since 2026-01-01 UTC, same as the iOS build
   number; gitignored).
4. `scripts/verify-native-sync.mjs android`: the app's copy matches
   `dist-native/` file for file.

Gradle never runs any of this. **A release build refuses to start without
`version.properties`**, i.e. without `android:prep`. A debug build (Android
Studio's Run button) does not refuse, and takes whatever is in
`assets/public` — run `android:prep` first.

If a build fails with a resource "not found" that plainly exists, it is
Gradle's incremental cache after resources moved: `./gradlew clean` and rebuild.

## Versions

- **versionName** (`1.0.0`): `android/app/build.gradle`. Bump by hand per store
  release, with the iOS `MARKETING_VERSION`.
- **versionCode:** generated by `android:prep`. Never write a literal into
  `build.gradle`; `stamp-android-build.mjs` refuses to run if you do.

## Signing (once, by Tom)

Google Play uses **Play App Signing**: Google holds the key that signs what
users install, and you sign uploads with an **upload key** you keep. Losing the
upload key is recoverable (Play Console → App integrity → request an upload key
reset); it is still a secret.

1. Make the upload key and back it up (1Password). It lives at the root of the
   main checkout, `~/dev/kenworthy-ticketing-build/kenworthy-upload.keystore`,
   where git ignores it (`*.keystore` in `.gitignore` and in `.git/info/exclude`):

   ```sh
   keytool -genkeypair -v -keystore ~/dev/kenworthy-ticketing-build/kenworthy-upload.keystore -alias kenworthy-upload \
     -keyalg RSA -keysize 2048 -validity 10000
   ```

2. Create `android/keystore.properties` (gitignored, as are `*.jks` and
   `*.keystore`):

   ```properties
   storeFile=/Users/thecommodore/dev/kenworthy-ticketing-build/kenworthy-upload.keystore
   storePassword=…
   keyAlias=kenworthy-upload
   keyPassword=…
   ```

   `storeFile` is relative to `android/` unless absolute. Each worktree needs
   its own copy of this file (it is not tracked).

Without `keystore.properties` a release build comes out **unsigned**, which
neither Play nor a phone will accept. Check a build with
`$ANDROID_HOME/build-tools/36.0.0/apksigner verify --print-certs <apk>`.

## Distribute

### Google Play, Internal testing (the TestFlight equivalent)

1. One-time: a Google Play developer account ($25) — ideally under
   `tickets@kenworthy.org`, as with Apple. An organisation account needs a
   D-U-N-S number; Apple's organisation enrolment required one too, so it
   should already exist (not checked).
2. Play Console → **Create app** → name Kenworthy, App, Free.
3. **Testing → Internal testing → Create new release.** Accept Play App
   Signing, upload `app-release.aab`.
4. **Testers:** create an email list (up to 100) and share the opt-in link.
   Internal-track builds reach testers in minutes, without full review.

Play will not let the release out until the app's **Policy → App content**
items are answered (privacy policy URL, data safety, ads, target audience,
content rating). The privacy policy is `https://kenworthy.org/privacy`.

### Firebase App Distribution (no Play account)

Upload `app-release.apk` (signed with the upload key) to a Firebase project →
App Distribution, invite testers by email. Testers install Firebase's tester
app once. Quickest way onto staff phones; does not lead to a store listing.

### Sideload (a couple of devices)

`adb install app-release.apk`, or send the APK and let the phone "install
unknown apps". Fine for a look; not for a tester group.

## Test on the emulator

```sh
$ANDROID_HOME/emulator/emulator -avd Medium_Phone_API_37.0 &
cd android && ./gradlew assembleDebug
$ANDROID_HOME/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
$ANDROID_HOME/platform-tools/adb shell am start -n org.kenworthy.tickets/.MainActivity
```

A debug build has WebView debugging on. Open `chrome://inspect` in desktop
Chrome, or script it:
`adb forward tcp:9222 localabstract:webview_devtools_remote_$(adb shell pidof org.kenworthy.tickets)`
then use the DevTools protocol at `http://localhost:9222/json`.

**Navigate with real taps (`adb shell input tap x y`), not scripted clicks**,
when testing the back button: Chrome skips history entries made without a user
gesture, so a click fired over DevTools makes "back" look broken when it isn't.

## Icons and launch screen

`sh scripts/android-icons.sh` regenerates them from `public/icons/icon.svg`
(macOS, `sips`): an adaptive icon whose foreground is a vector of the mark on
`#0f0f0f`, the legacy PNGs for Android 7, and the launch screen, which reuses
the foreground. Re-measure the mark's bounds in the script if the SVG changes.
