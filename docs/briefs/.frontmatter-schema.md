# Brief frontmatter schema

`scripts/generate-tasks.mjs` parses these fields to build `docs/TASKS.md`. If a
field is missing or misspelled the brief still appears in the catalogue, but
under **Needs triage** rather than where it belongs — the generator never
guesses.

Frontmatter goes at the very top of the file, before the `#` heading.

```yaml
---
brief: readability-font-size
title: Raise default readability and font size across the platform
status: shipped
track: ux
severity: P2
date: 2026-08-15
shipped_in: ["#100", "#101"]
shipped_at: 2026-08-19
verified: true
findings: FINDINGS-readability-font-size.md
---
```

## Fields

| field | required | meaning |
|---|---|---|
| `brief` | yes | filename without `BRIEF-` and `.md`. Must match the file. |
| `title` | yes | one line, states the outcome. Not the filename reworded. |
| `status` | yes | see below |
| `track` | yes | `bug` · `feature` · `ux` · `ops` · `security` · `data` · `docs` |
| `severity` | open items only | `P0` launch-blocking · `P1` soon · `P2` backlog · `P3` nice-to-have |
| `date` | yes | when the brief was written (`YYYY-MM-DD`) |
| `shipped_in` | when shipped | list of PR numbers and/or commit SHAs |
| `shipped_at` | when shipped | `YYYY-MM-DD` |
| `verified` | yes | `true` only if `shipped_in` was checked against the repo |
| `supersedes` / `superseded_by` | when applicable | **set both sides, always** |
| `evidence` | optional | what proves it shipped when there is no clean commit to cite — a file, a migration, an observed behaviour |
| `findings` | optional | companion `FINDINGS-*.md` or `*-OUTCOME.md` |
| `closed_reason` | when closed | one line, required for `closed-not-a-bug` |

## `status` values

| value | meaning |
|---|---|
| `queued` | written, not started |
| `in-progress` | someone is on it now |
| `built` | code complete, **not deployed to production** |
| `shipped` | in production |
| `closed-not-a-bug` | investigated and closed; `closed_reason` required |
| `superseded` | replaced; `superseded_by` required |
| `needs-triage` | status is not trustworthy and must be re-established |

## `verified` is the important one

`verified: false` means the status is what the document *claims*, not something
anyone checked. This distinction exists because it has already gone wrong twice
on this project:

- Nineteen briefs sat untracked with stale status lines while all nineteen were
  in production.
- `BRIEF-past-no-purchase` was committed by **the very PR that fixed it** and
  kept its "Architectural gap" flag, so it read as outstanding launch-critical
  work.

A brief that shipped but still reads open sends a later session to re-implement
finished work. Treat `verified: false` as a question, never as a status.

To verify: find the commit or PR that closed it, confirm the change is actually
on `main`, record it in `shipped_in`, then set `verified: true`.

Not everything has a clean commit to point at. Some of this work predates the
current commit conventions and landed under messages like "Changes", and some
of it is a data backfill rather than a diff. Where that is so, cite the proof
in `evidence` — the migration, the file and line, the row counts, the behaviour
observed in production. An artifact you checked is evidence; a commit message
that merely mentions the topic is not.

## Lifecycle

Each transition is followed by re-running the generator.

- **Shipping** — set `status: shipped`, `shipped_in`, `shipped_at`,
  `verified: true`. Commit the frontmatter change *alongside* the ship commit,
  not after it.
- **Superseding** — set `superseded_by` on the old brief and `supersedes` on the
  new one. Both sides. A one-sided link is how a dead brief gets executed.
- **Closing without shipping** — `status: closed-not-a-bug` and a one-line
  `closed_reason`. Closing with the reason recorded is a finding, not a failure,
  and is often the most useful thing a session produces.

## Files without frontmatter

`FINDINGS-*.md` and `*-OUTCOME.md` are companion documents, not units of work.
They carry no frontmatter and are not catalogued; link them from their brief's
`findings:` field instead.
